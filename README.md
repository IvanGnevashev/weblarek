# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между слоями реализовано с помощью брокера событий `EventEmitter`. Классы представления вызывают callback-функции, полученные через конструктор. Переданные callback-функции генерируют события о действиях пользователя.

Презентер в файле `main.ts` обрабатывает события, вызывает методы моделей и обновляет представление. После изменения данных модели самостоятельно генерируют события через общий экземпляр `EventEmitter`.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн «Наблюдатель». Он позволяет подписываться на события и генерировать их, обеспечивая слабую связанность между моделями, представлениями и Презентером.

В приложении создаётся один основной экземпляр `EventEmitter`. Он передаётся моделям, а также используется callback-функциями представлений и обработчиками в `main.ts`.

Конструктор:
`constructor()` — создаёт пустую коллекцию событий и обработчиков.

Поля класса:
- `_events: Map<EventName, Set<Subscriber>>` — коллекция подписок. Ключом является название события или регулярное выражение, значением — набор обработчиков.

Методы класса:
- `on<T extends object>(eventName: EventName, callback: (event: T) => void): void` — подписывает обработчик на событие.
- `off(eventName: EventName, callback: Subscriber): void` — удаляет указанную подписку.
- `emit<T extends object>(eventName: string, data?: T): void` — генерирует событие и передаёт данные его обработчикам.
- `onAll(callback: (event: EmitterEvent) => void): void` — подписывает обработчик на все события.
- `offAll(): void` — удаляет все подписки.
- `trigger<T extends object>(eventName: string, context?: Partial<T>): (data: T) => void` — создаёт callback-функцию, которая при вызове генерирует указанное событие.

## Данные
В приложении используются следующие интерфейсы и типы данных:

### Интерфейс IProduct
Описывает структуру данных товара в каталоге интернет-магазина.

```typescript
interface IProduct {
  id: string;           // Уникальный идентификатор товара
  description: string;  // Описание товара
  image: string;        // URL изображения товара
  title: string;        // Название товара
  category: string;     // Категория товара
  price: number | null; // Цена товара (null, если цена не указана)
}
```
### Интерфейс IProductListResponse
Описывает ответ сервера на запрос каталога товаров.

```typescript
interface IProductListResponse {
  total: number;
  items: IProduct[];
}
```

### Интерфейс IOrderRequest
Описывает данные заказа, отправляемые на сервер.

```typescript
interface IOrderRequest extends IBuyer {
    total: number;
    items: string[];
}
```


### Интерфейс IOrderResponse
Описывает ответ сервера на оформление заказа.

```typescript
interface IOrderResponse {
    id: string;
    total: number;
}
```

### Тип TPayment
Описывает доступные способы оплаты.

```typescript
type TPayment = 'card' | 'cash';
```

### Интерфейс IBuyer
Описывает структуру данных покупателя при оформлении заказа.

```typescript
interface IBuyer {
  payment: TPayment | null;  // Способ оплаты ('card' | 'cash';)
  email: string;      // Email покупателя
  phone: string;      // Телефон покупателя
  address: string;   // Адрес доставки
}
```
### Тип IValidationErrors
Тип для ошибок валидации покупателя. Ключи соответствуют полям `IBuyer`, значения — строки с текстом ошибки.

```typescript
type IValidationErrors = Partial<Record<keyof IBuyer, string>>;
```

## Модели данных

Модели отвечают за хранение и изменение данных приложения. Каждая модель получает брокер событий через конструктор и генерирует событие после изменения своих данных.

### Класс CatalogModel

Отвечает за хранение каталога товаров и товара, выбранного для подробного просмотра.

Конструктор:
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:
- `_items: IProduct[]` — массив товаров каталога.
- `_preview: IProduct | null` — товар, выбранный для подробного просмотра.
- `_events: IEvents` — брокер событий.

Методы класса:
- `setItems(items: IProduct[]): void` — сохраняет каталог и генерирует событие `catalog:changed`.
- `getItems(): IProduct[]` — возвращает массив товаров.
- `getItem(id: string): IProduct | undefined` — возвращает товар по идентификатору.
- `setPreview(item: IProduct | null): void` — сохраняет выбранный товар и генерирует событие `preview:changed`.
- `getPreview(): IProduct | null` — возвращает выбранный товар.

### Класс BasketModel

Отвечает за хранение товаров, добавленных в корзину.

Конструктор:
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:
- `_items: IProduct[]` — массив товаров в корзине.
- `_events: IEvents` — брокер событий.

Методы класса:
- `getItems(): IProduct[]` — возвращает товары корзины.
- `addItem(item: IProduct): void` — добавляет товар и генерирует событие `basket:changed`.
- `removeItem(id: string): void` — удаляет товар и генерирует событие `basket:changed`.
- `clear(): void` — очищает корзину и генерирует событие `basket:changed`.
- `getTotal(): number` — возвращает общую стоимость товаров.
- `getCount(): number` — возвращает количество товаров.
- `hasItem(id: string): boolean` — проверяет наличие товара по идентификатору.

### Класс BuyerModel

Отвечает за хранение, валидацию и очистку данных покупателя.

Конструктор:
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:
- `_payment: TPayment | null` — способ оплаты.
- `_address: string` — адрес доставки.
- `_email: string` — электронная почта.
- `_phone: string` — номер телефона.
- `_events: IEvents` — брокер событий.

Методы класса:
- `emitChanges(): void` — защищённый метод, генерирующий событие `buyer:changed`.
- `setPayment(payment: TPayment): void` — сохраняет способ оплаты и генерирует `buyer:changed`.
- `setAddress(address: string): void` — сохраняет адрес и генерирует `buyer:changed`.
- `setEmail(email: string): void` — сохраняет электронную почту и генерирует `buyer:changed`.
- `setPhone(phone: string): void` — сохраняет телефон и генерирует `buyer:changed`.
- `getData(): IBuyer` — возвращает все данные покупателя.
- `clear(): void` — очищает данные и генерирует `buyer:changed`.
- `validate(): IValidationErrors` — проверяет данные и возвращает объект ошибок.

## Слой коммуникации

Слой коммуникации отвечает за обмен данными между приложением и сервером. Он получает каталог товаров и отправляет оформленный заказ. Для выполнения HTTP-запросов используется объект, соответствующий интерфейсу `IApi`.

### Класс LarekApi

Класс предоставляет методы для работы с API интернет-магазина. Он не наследует класс `Api`, а получает готовый объект для выполнения запросов через конструктор. Такой подход называется композицией.

Конструктор:
`constructor(api: IApi)` — принимает объект, который умеет выполнять `GET`- и `POST`-запросы.

Поля класса:
- `_api: IApi` — объект для отправки запросов на сервер.

Методы класса:
- `getProducts(): Promise<IProductListResponse>` — отправляет запрос на эндпоинт `/product/` и возвращает список товаров.
- `postOrder(orderData: IOrderRequest): Promise<IOrderResponse>` — отправляет данные заказа на эндпоинт `/order/` и возвращает результат оформления заказа.

## Слой представления

Классы слоя представления отвечают за работу с DOM и обработку действий пользователя. Они не обращаются к моделям и не содержат бизнес-логику. Данные передаются компонентам через метод `render()` и сеттеры.

О действиях пользователя компоненты сообщают с помощью callback-функций, полученных через конструктор. В `main.ts` в эти callback-функции передаётся генерация соответствующего события через `EventEmitter`.

### Базовые классы

#### Класс Card

Базовый класс для карточек товара. Наследует класс `Component`. Отвечает за отображение общих для всех карточек данных: названия и цены товара.

Конструктор:
`constructor(container: HTMLElement)` — принимает корневой DOM-элемент карточки.

Поля класса:
- `_title: HTMLElement` — элемент с названием товара.
- `_price: HTMLElement` — элемент с ценой товара.

Методы класса:
- `set title(value: string): void` — устанавливает название товара.
- `set price(value: number | null): void` — устанавливает цену товара. Если цена равна `null`, отображает текст «Бесценно».

Вспомогательная функция:
- `setCategory(element: HTMLElement, value: string): void` — устанавливает название категории, удаляет предыдущий CSS-класс категории и добавляет соответствующий класс из `categoryMap`. Функция используется только в `CardCatalog` и `CardPreview`. Вынесенна в `Card` чтобы не дублировать логику.

#### Класс Form

Базовый класс для форм оформления заказа. Наследует класс `Component`. Отвечает за обработку ввода, отправку формы, состояние кнопки отправки и вывод ошибок.

Конструктор:
`constructor(container: HTMLElement, ...)` — принимает DOM-элемент формы, callback изменения поля и callback отправки формы.

Поля класса:
- `_submit: HTMLButtonElement` — кнопка отправки формы.
- `_errors: HTMLElement` — элемент для вывода сообщений об ошибках.

Методы класса:
- `set valid(value: boolean): void` — включает или отключает кнопку отправки формы.
- `set errors(value: string): void` — выводит сообщение об ошибке.
- обработчик события `input` передаёт Презентеру имя изменённого поля и его новое значение.
- обработчик события `submit` отменяет стандартную отправку формы и вызывает переданный callback.

### Компоненты представления

Конструктор:
`constructor(container: HTMLElement, onClose: () => void)` — принимает DOM-элемент модального окна и callback его закрытия.

Поля класса:
- `_close: HTMLButtonElement` — кнопка закрытия модального окна.

Поля класса:
- `_image: HTMLImageElement` — изображение товара.
- `_category: HTMLElement` — элемент с категорией товара.

Методы класса:
- `set image(value: string): void` — устанавливает изображение товара.

#### Класс CardPreview

Отвечает за подробное отображение выбранного товара в модальном окне. Наследует класс `Card`. Один экземпляр `CardPreview` создаётся при загрузке приложения и повторно используется для отображения разных товаров.

Конструктор:
`constructor(container: HTMLElement, onButtonClick: () => void)` — принимает DOM-элемент карточки и callback нажатия на основную кнопку.

Поля класса:
- `_image: HTMLImageElement` — изображение товара.
- `_category: HTMLElement` — элемент с категорией товара.
- `_description: HTMLElement` — описание товара.
- `_button: HTMLButtonElement` — кнопка добавления товара в корзину или удаления из неё.

Методы класса:
- `set image(value: string): void` — устанавливает изображение товара.
- `set category(value: string): void` — устанавливает название категории и соответствующий ей CSS-класс.
- `set description(value: string): void` — устанавливает описание товара.
- `set buttonText(value: string): void` — устанавливает готовый текст кнопки.
- `set buttonDisabled(value: boolean): void` — включает или блокирует кнопку.
- обработчик клика по кнопке вызывает переданный callback.

#### Класс CardBasket

Отвечает за отображение товара в списке корзины. Наследует класс `Card`.

Конструктор:
`constructor(container: HTMLElement, onDeleteClick: () => void)` — принимает DOM-элемент карточки и callback удаления товара.

Поля класса:
- `_index: HTMLElement` — порядковый номер товара в корзине.
- `_delete: HTMLButtonElement` — кнопка удаления товара.

Методы класса:
- `set index(value: number): void` — устанавливает порядковый номер товара.
- обработчик клика по кнопке удаления вызывает переданный callback.

#### Класс Basket

Отвечает за отображение корзины, списка выбранных товаров и общей стоимости. Наследует класс `Component`.

Конструктор:
`constructor(container: HTMLElement, onSubmitClick: () => void)` — принимает DOM-элемент корзины и callback перехода к оформлению заказа.

Поля класса:
- `_price: HTMLElement` — элемент с общей стоимостью товаров.
- `_basketList: HTMLElement` — контейнер списка товаров.
- `_submit: HTMLButtonElement` — кнопка оформления заказа.

Методы класса:
- `set items(value: HTMLElement[]): void` — отображает переданные карточки товаров и блокирует кнопку оформления, если массив пуст.
- `set total(value: number): void` — отображает общую стоимость товаров.
- обработчик клика по кнопке оформления вызывает переданный callback.

#### Класс FormOrder

Отвечает за первый шаг оформления заказа: выбор способа оплаты и ввод адреса. Наследует класс `Form`.

Конструктор:
`constructor(container: HTMLElement, onInputChange: (field: string, value: string) => void, onPaymentChange: (payment: TPayment) => void, onSubmit: () => void)` — принимает DOM-элемент формы и callback-функции изменения поля, выбора оплаты и отправки формы.

Поля класса:
- `_address: HTMLInputElement` — поле ввода адреса.
- `_cardButton: HTMLButtonElement` — кнопка выбора оплаты онлайн.
- `_cashButton: HTMLButtonElement` — кнопка выбора оплаты при получении.

Методы класса:
- `set payment(value: TPayment): void` — отображает выбранный способ оплаты.
- `set address(value: string): void` — устанавливает значение поля адреса.
- обработчики кнопок оплаты передают Презентеру выбранный способ оплаты.

#### Класс FormContacts

Отвечает за второй шаг оформления заказа: ввод электронной почты и телефона. Наследует класс `Form`.

Конструктор:
`constructor(container: HTMLElement, onInputChange: (field: string, value: string) => void, onSubmit: () => void)` — принимает DOM-элемент формы и callback-функции изменения поля и отправки формы.

Поля класса:
- `_email: HTMLInputElement` — поле ввода электронной почты.
- `_phone: HTMLInputElement` — поле ввода телефона.

Методы класса:
- `set email(value: string): void` — устанавливает значение поля электронной почты.
- `set phone(value: string): void` — устанавливает значение поля телефона.

#### Класс Success

Отвечает за отображение сообщения об успешном оформлении заказа. Наследует класс `Component`.

Конструктор:
`constructor(container: HTMLElement, onClose: () => void)` — принимает DOM-элемент сообщения и callback закрытия.

Поля класса:
- `_description: HTMLElement` — элемент с информацией о списанной сумме.
- `_close: HTMLButtonElement` — кнопка закрытия сообщения.

Методы класса:
- `set total(value: number): void` — отображает сумму оформленного заказа.
- обработчик клика по кнопке вызывает callback закрытия.

#### Класс Page

Отвечает за отображение каталога товаров и счётчика корзины на главной странице. Наследует класс `Component`.

Конструктор:
`constructor(container: HTMLElement, onBasketClick: () => void)` — принимает DOM-элемент страницы и callback открытия корзины.

Поля класса:
- `_gallery: HTMLElement` — контейнер карточек каталога.
- `_basketButton: HTMLButtonElement` — кнопка открытия корзины.
- `_counter: HTMLElement` — счётчик товаров в корзине.

Методы класса:
- `set catalog(value: HTMLElement[]): void` — отображает карточки товаров в каталоге.
- `set counter(value: number): void` — отображает количество товаров в корзине.
- обработчик клика по кнопке корзины вызывает переданный callback.

## События

Для связи слоёв используется единый экземпляр `EventEmitter`, созданный в `main.ts`.

Классы представления вызывают переданные через конструктор callback-функции. Эти callback-функции генерируют события о действиях пользователя. Презентер обрабатывает события, вызывает методы моделей и обновляет представление.

Модели самостоятельно генерируют события после изменения своих данных.

### События действий пользователя

| Событие | Инициатор | Данные | Назначение |
|---|---|---|---|
| `card:select` | `CardCatalog` | `{ id: string }` | Выбор товара для подробного просмотра |
| `preview:action` | `CardPreview` | — | Добавление выбранного товара в корзину или удаление из неё |
| `basket:open` | `Page` | — | Открытие корзины |
| `basket:remove` | `CardBasket` | `{ id: string }` | Удаление товара из корзины |
| `order:open` | `Basket` | — | Открытие первого этапа заказа |
| `order:input` | `FormOrder` | `{ field: string, value: string }` | Изменение адреса |
| `order:payment` | `FormOrder` | `{ payment: TPayment }` | Изменение способа оплаты |
| `order:submit` | `FormOrder` | — | Переход к форме контактов |
| `contacts:input` | `FormContacts` | `{ field: string, value: string }` | Изменение email или телефона |
| `contacts:submit` | `FormContacts` | — | Отправка заказа |
| `modal:close` | `Modal`, `Success` | — | Закрытие модального окна |

### События моделей данных

| Событие | Модель | Данные | Когда генерируется |
|---|---|---|---|
| `catalog:changed` | `CatalogModel` | — | После сохранения каталога |
| `preview:changed` | `CatalogModel` | — | После изменения выбранного товара |
| `basket:changed` | `BasketModel` | — | После добавления, удаления или очистки товаров |
| `buyer:changed` | `BuyerModel` | — | После изменения или очистки данных покупателя |

### Основные последовательности событий

Загрузка каталога:

API
  получение каталога
  добавление CDN_URL к путям изображений в Презентере
  CatalogModel.setItems()
  catalog:changed
  отображение карточек в Page

Выбор товара:

CardCatalog
  card:select
  CatalogModel.setPreview()
  preview:changed
  отображение CardPreview в Modal

Изменение корзины:

  CardPreview или CardBasket
  preview:action или basket:remove
  изменение BasketModel
  basket:changed
  обновление Basket и счётчика Page

Оформление заказа:

FormOrder
  order:input / order:payment
  изменение BuyerModel
  buyer:changed
  валидация и обновление FormOrder

FormContacts
  contacts:input
  изменение BuyerModel
  buyer:changed
  валидация и обновление FormContacts

FormContacts
  contacts:submit
  отправка данных через LarekApi
  при успешном ответе Презентер очищает модели и отображает Success
  при ошибке Презентер выводит сообщение в FormContacts
